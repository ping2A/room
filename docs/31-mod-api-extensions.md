# 31 — Mod API extensions: states, weapons, generated content

**Audience:** an external coding agent working in the Room repo. Read
`AGENTS.md`, `docs/02-conventions.md` (§Determinism), `docs/08-actors.md`,
`docs/12-wasm-scripting.md` (§5–§6 ABI/registration, §15 status) and
`docs/30-weapons-audit.md` (weapon logic, flash, ammo rules) first.
**Status:** **MA1**–**MA4** done (`wasm_mod_lumps`, slots/alt fire/hit info/
ThingDestroyed/`[options]`; acceptance via `docs/32` + `wasm_mod_shuriken`).
Milestones `MA1`–`MA4` (§5).
**Companion:** `docs/32-shuriken-mod.md` is the first mod built on these
extensions (a throwing weapon generated entirely at startup) and is the
acceptance case for this document.

**Goal.** Let a WASM mod define a complete, native-quality weapon (or any
actor) **in code during `room_register()`**: its own states and animations,
weapon/ammo/inventory/projectile properties, actions (native or WASM), weapon
slot, alt fire, and its own **sprites and sounds generated at startup** —
with everything deterministic so netplay, demos, saves and the server
verifier keep working.

---

## 0. TL;DR

1. **MA1–MA4 landed.** Mods can merge states/actions, set weapon/ammo props,
   generate lumps, assign weapon slots, use alt fire, read missile hit info,
   handle `THING_DESTROYED`, and read identical `[options]` from the manifest.
2. Acceptance case: `docs/32` shuriken mod (`wasm_mod_shuriken`).
3. Everything a module generates must be **bit-identical on every machine**;
   the registration fingerprint covers generated bytes so mismatches fail the
   room's mod check instead of desyncing later.
4. All imports are **append-only** in the IDL and linker tables (ABI stays v1).

## 1. What exists vs. what is missing

| Need | Exists | Missing |
|---|---|---|
| New classes from a mod | `reg_class_begin/end`, `reg_class_property_i32/str`, `reg_class_flag` → `import_script_class` (copies the parent, applies props/flags) | — |
| Own states | `reg_state_label`, `reg_state(sprite, frame, tics, flags, callback_id)` are recorded in `RegisteredClass.states` | **Not merged** into `StateTable`; no flow keywords (`Loop/Stop/Goto/Wait`), no native action binding, no action args |
| Actions | Native actions via `call_action_args` (DECORATE path) | Binding from module states; dispatching `callback_id` actions to WASM for actors **and** psprites |
| Weapon / ammo / inventory / projectile properties | `PropId` 1–12, 20–22 (health, speed, radius, …, translation, tag, obituary) | `Weapon.*`, `Inventory.*`, `Ammo.*`, `Damage`, `SeeSound/DeathSound/BounceSound`, bounce props, `Inventory.Icon`, pickup message/sound |
| Flags | `class_flag` 1–11 (SOLID … DONTDRAW) | `MISSILE`, `NOGRAVITY` exists, `DROPOFF`, `NOBLOCKMAP`, `NOTELEPORT`, `BOUNCEONACTORS`, `THRUGHOST`, `INVENTORY.*`, `WEAPON.NOALERT`, `WEAPON.NOAUTOFIRE`, `FLATSPRITE`/`WALLSPRITE` render flags |
| Sprites / graphics | Sprites come from the VFS (`S_START…S_END`, `SoftPatch`) | Any way for a module to provide image data |
| Sounds | SNDINFO + DMX/WAV lumps in the VFS | Any way for a module to provide sound data |
| Weapon slots | `reg_weapon_slot` + `Weapon.SlotNumber` → `WeaponSlots` | — |
| Alt fire | `Buttons::ALTATTACK`, RMB / `+altattack`, `AltFire`/`AltHold` via `A_WeaponReady`/`A_ReFire` | — |
| Missile impact info | `hit_kind` / `hit_actor` / `actor_hit_info` on Death | — |
| Palette | PLAYPAL in the VFS | A read-only `lump_read` import usable at registration (listed in `docs/12` §9, not implemented) |

## 2. Engine work (`MA*`)

All new imports follow the usual rules (`docs/27` §10): append-only in the
IDL (`crates/room-script-abi/api/reg.ron`, `common.ron`) and the
`game_fns!`/registration linker tables, SDK wrappers
(`crates/room-script-sdk/src/reg.rs`, new `art.rs`, `sound.rs`), AssemblyScript
mirror (`crates/room-web/as/room.ts`), tests, `docs/12` §15/§16 updates.

### MA1 — Module states and actions
1. **Merge states**: in `ModRuntime::merge_classes`
   (`crates/room-sim/src/script_mods.rs`), append each class's recorded
   states to the `StateTable` (new `StateTable::import_script_states(class_id, &[RegCall])`),
   register its labels for that class, then run `inherit_labels` so labels
   not defined by the module still come from the parent (`Spawn`, `Death`, …).
2. **Flow keywords**: add `reg_state_flow(kind, label_ptr, len, offset)` —
   kinds `Loop`, `Stop`, `Wait`, `Fail`, `Goto` (label may be `Super::X` or a
   label of the parent chain). Apply exactly like DECORATE; an unresolved
   `Goto` is a **registration error** (never falls through — see
   `docs/30` N1).
3. **Native actions on states**: `reg_state_action(name_ptr, len, args_ptr, args_len)`
   sets the action of the *last* appended state; `args` is the DECORATE
   argument string (`"\"ShurikenMissile\", 0, true"`), parsed by the existing
   `deco_eval` so every native action (`A_WeaponReady`, `A_Lower`, `A_Raise`,
   `A_ReFire`, `A_FireProjectile`, `A_PlaySound`/`A_StartSound`,
   `A_SpawnItemEx`, `A_Jump`, …) is available. Unknown action names are a
   registration error.
4. **WASM actions**: `reg_state(…, callback_id)` with `callback_id ≥ 0`
   makes the state call `room_dispatch(callback_id, ActionPayload)` when
   entered. `ActionPayload { self_: ActorRef, player: i32 /* −1 or slot */,
   state: StateRef, caller: u32 /* 0 actor, 1 psprite, 2 flash */ }`. For
   psprite states `self_` is the player's body (as in GZDoom) and
   `world.psprite_weapon` is set (needed for ammo). The returned `i64` is a
   `StateRef` to jump to (0 = continue). Wire this both in the actor state
   machine (`room-sim` thinker state advance) and in
   `think_player::set_psprite` (`other =>` branch).
5. **Registration flags**: `reg_state` flag bits: `BRIGHT`, `FAST`,
   `CANRAISE`, `NODELAY`, `OFFSET(x,y)` via a separate
   `reg_state_offset(x, y)` for weapon frames.
6. Fingerprint (`RegistrationSession::fingerprint`) already hashes the call
   list; make sure the new calls are recorded.

### MA2 — Weapon, ammo, inventory and projectile properties
Extend `PropId` (append-only) and `apply_script_prop_i32/str`
(`crates/room-sim/src/class.rs`):

| PropId | Kind | Maps to |
|---|---|---|
| `InventoryAmount`, `InventoryMaxAmount` | i32 | `inventory_amount`, `inventory_max_amount` |
| `InventoryPickupMessage`, `InventoryPickupSound`, `InventoryIcon` | str | pickup message / sound / HUD icon |
| `AmmoBackpackAmount`, `AmmoBackpackMaxAmount` | i32 | backpack rules (`pickup.rs`) |
| `WeaponAmmoType` | str | `ammo_type` |
| `WeaponAmmoUse`, `WeaponAmmoGive`, `WeaponSelectionOrder`, `WeaponKickback`, `WeaponSlotNumber` | i32 | existing `ClassDef` fields (`selection_order` exists since WF1) |
| `WeaponReadySound`, `WeaponUpSound` | str | (also fixes `docs/30` N7) |
| `Damage` | i32 | missile damage (`((P_Random()%8)+1)·Damage`) |
| `SeeSound`, `DeathSound`, `BounceSound`, `ActiveSound` | str | existing sound fields |
| `BounceType` (0 none … GZDoom enum), `BounceCountMax`, `BounceFactorPercent`, `WallBounceFactorPercent` | i32 | bounce fields (if the playsim supports them; else MA2b) |
| `ProjectileKickBack` | i32 | kickback |

New `class_flag` ids: `MISSILE`, `DROPOFF`, `NOBLOCKMAP`, `NOTELEPORT`,
`BOUNCEONACTORS`, `THRUGHOST`, `NOBLOODDECALS`, `FORCEXYBILLBOARD`,
`WALLSPRITE`, `FLATSPRITE`, `INVENTORY_AUTOACTIVATE`, `WEAPON_NOALERT`,
`WEAPON_NOAUTOFIRE`, `WEAPON_AMMO_OPTIONAL`.
`is_weapon` / `is_ammo` / `is_inventory` must be set when the corresponding
properties are present (same rule as DECORATE in `class.rs`), or when the
parent is `Weapon` / `Ammo` / `Inventory` (see `docs/30` W16 — base classes).

`+WEAPON.NOALERT`: skip `noise_alert` in `fire_weapon` and the `A_ReFire`
branch of `think_player.rs` when the ready weapon has the flag.

### MA3 — Generated lumps: graphics and sounds
Design: the module produces **lumps in standard Doom formats**; the host
collects them into an **in-memory PWAD layer** mounted on top of the VFS
(after the mod's own WAD). Everything downstream (sprite lookup, `SoftPatch`,
GPU textures, software renderer, sound system, `drop_weapons_without_sprites`,
web) works unchanged.

Imports (registration scope only):
```
lump_find(name_ptr, len, namespace) -> i32         // common; read-only; −1 if absent
lump_read(index, buf_ptr, cap) -> i32               // common; bytes copied (PLAYPAL, COLORMAP…)
reg_lump(name_ptr, name_len, namespace, data_ptr, data_len) -> i32   // reg; 0 ok
```
- `namespace`: `0 global`, `1 sprites (S_START)`, `2 graphics`, `3 sounds`,
  `4 flats`. Names ≤ 8 chars, uppercase; a name already present in the
  module's own WAD is an error; overriding IWAD lumps requires a manifest
  flag (`override_lumps = true`).
- Limits: 4 MiB total per mod, 256×256 max per graphic, 10 s per sound.
- The SDK provides encoders (pure Rust, `no_std`, `alloc` optional):
  `art::encode_patch(w, h, left, top, &indexed, &mask) -> Vec<u8>` (Doom patch:
  header + column posts; transparent where `mask = 0`) and
  `sound::encode_dmx(rate, &pcm_u8) -> Vec<u8>` (DMX: `u16 3, u16 rate, u32 n,
  16 pad bytes, samples, 16 pad bytes`).
- SNDINFO entries: `reg_sound_alias(logical_ptr, len, lump_ptr, len)` so
  states can use logical names (`"shuriken/throw"`); also `$limit`-style
  options as an int arg.
- Host side: `RegistrationSession` gains `lumps: Vec<GeneratedLump>`;
  `Headless::set_script_mods` returns them; desktop (`room-app`), web
  (`room-web`) and the server verifier mount them as a memory WAD
  (`VfsBuilder` already mounts in-memory WADs in tests via `WadWriter`) and
  invalidate patch/sprite/sound caches. Hot swap (`hot_swap_script_mods`)
  replaces the layer.
- Netplay: generation is deterministic, and the fingerprint hashes the lump
  bytes, so a client with different bytes fails the room's mod check instead
  of desyncing later.

### MA4 — Slots, alt fire, missile hit info, misc.
1. `reg_weapon_slot(slot, class_ptr, len, priority)` → KEYCONF
   `addslotdefault` semantics in `WeaponSlots`.
2. **Alt fire**: `Buttons::ALTATTACK = 1 << 9` (the wire field is already
   `u32` → no protocol change); bind `+altattack` (default: right mouse);
   `A_WeaponReady` enters `AltFire` when held (GZDoom `WRF_NOSECONDARY`
   respected), `A_ReFire` in an alt sequence re-enters `AltHold`/`AltFire`;
   `Weapon.AmmoUse2`/`AmmoType2` optional (else primary ammo with an explicit
   `useammo` count in the action). Update `docs/15` bindings and the web
   input hub.
3. **Missile hit info**: when a missile enters its `Death`/`Crash`/`XDeath`
   state, record on the missile actor: `hit_kind` (`1 actor, 2 wall, 3 floor,
   4 ceiling, 5 sky, 6 liquid floor`), `hit_actor` (blocking mobj),
   `hit_normal` (wall normal or ±Z), `hit_line`/`hit_sector`, and `hit_pos`.
   Expose with `actor_get_i32(HIT_KIND)`, `actor_get_ref(HIT_ACTOR)`, and a new
   `actor_hit_info(ref, out_ptr)` (pos xyz + normal xyz as f64). Sky hits
   already remove the missile silently in Doom; give the module a
   `MissileExpired` event (or a `Death` callback with `hit_kind = 5`) so it
   can account for the lost star.
4. **Events**: append `WORLD_THING_DESTROYED` (already planned, `docs/27` C8)
   so the mod can clean up stuck-star bookkeeping; `ThingDied` already exists
   for monsters.
5. `A_FireProjectile` must deplete ammo (fix `docs/30` N2) and honour
   `useammo`; `+WEAPON.NOALERT` (MA2).

### MA4b — Manifest options
Mods need configuration that is **identical on every client** (it changes
generated bytes and gameplay). Add a `[options]` table to `room.toml` /
`ROOMMOD` (parsed in `crates/room-script/src/manifest.rs`) and registration-
scope imports `manifest_option_i32(key_ptr, len, default) -> i32` and
`manifest_option_str(key_ptr, len, buf, cap) -> i32`. Values come from the
mounted manifest, so they are covered by the mod's fingerprint. Local cvars
must never influence registration.

## 3. Rules for modules using these APIs

- **Determinism of generation**: integer / Q16.16 maths only during
  registration; trigonometry from a const table (play-scope `math_*` imports
  are not available while registering); fixed-seed PRNG; index-order
  iteration; no pointer hashing. Recommend `clippy::float_arithmetic` on
  generation modules.
- **Budgets**: registration runs under the normal fuel budget (50 M
  instructions per call, `docs/12` §4.2). Generated lumps: 4 MiB per mod,
  256×256 per graphic, 10 s per sound.
- **Names**: lump names ≤ 8 chars, uppercase, unique within the mod;
  overriding IWAD lumps only with `override_lumps = true` in the manifest.
  Class names are global — prefix-free but documented in the mod's README.
- **Errors are fatal at registration** (unknown action, unresolved `Goto`,
  bad property type, oversized lump): the mod is rejected with a clear
  message; the game continues without it.
- **Hot swap**: changes to classes/states/lumps require a level restart
  (same rule as today for added classes); the lump layer is replaced on swap.
