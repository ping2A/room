# 31 — Shuriken mod: a weapon generated at startup (`mods/doom1-shuriken`)

**Audience:** an external coding agent working in the Room repo. Read
`AGENTS.md`, `docs/02-conventions.md` (§Determinism), `docs/08-actors.md`,
`docs/12-wasm-scripting.md` (§5–§6 ABI/registration, §15 status) and
`docs/30-weapons-audit.md` (weapon logic, flash, ammo rules) first.
**Status:** proposal. Engine milestones `SK-E0`–`SK-E4`, mod milestones
`SK0`–`SK4` (§10).

**Idea.** A WASM mod that adds a throwing weapon — **shurikens** — to any
Doom game. Nothing is shipped as art or data files: during `room_register()`
the mod **generates everything in code**: sprites (drawn from vector shapes
and quantised to the game's palette), sounds (synthesised PCM), the ammo,
weapon, projectile and pickup classes, their states and their behaviour.
The result behaves like a native weapon: slot key, pickups, HUD icon, ammo
counter, obituaries, works in netplay, demos and on the server verifier.

---

## 0. TL;DR

1. **Today a mod cannot do this.** Mod classes only get i32/string
   properties and flags (`ClassRegistry::import_script_class`); `reg_state`
   calls are recorded but **not merged** (`ModRuntime::merge_classes` only
   clones the base `StateTable`); there are no weapon/ammo/inventory/
   projectile properties, no way to bind actions to states, no way to add
   sprites or sounds, no slot registration, no alt-fire button. `docs/12`
   §15 lists "custom states from modules" as not done.
2. Build the engine pieces first (§3, `SK-E*`): module states + actions,
   weapon/ammo/projectile properties, **generated lumps** (graphics and
   sounds as an in-memory PWAD layer), weapon slots, `ALTATTACK`, missile
   hit info, `+WEAPON.NOALERT`.
3. Then the mod (§4–§7, `SK*`): `art.rs` (rasteriser), `synth.rs` (sound),
   `classes.rs` (registration), `behaviour.rs` (impact, sticking,
   retrieval, placement).
4. Everything generated must be **bit-identical on every machine**: integer
   / fixed-point maths only, no host randomness, no std floats with
   transcendental functions. The registration fingerprint covers the
   generated bytes.

## 1. Game design

| Aspect | Design |
|---|---|
| Name / tag | "Shuriken" (`Tag`), obituary "%o was diced by %k's shuriken." |
| Slot | Key **8** by default (free in Doom; configurable in `room.toml`, §4.6) |
| Ammo | `ShurikenAmmo`: max 30, backpack doubles to 60; weapon pickup gives 10, `ShurikenBox` gives 10, one retrieved star gives 1 |
| Primary fire | Throw one star. Fast (`Speed 30`; rocket 20, plasma 25), small (`Radius 6`, `Height 6`), `Damage 3` → Doom projectile damage `((P_Random()%8)+1)·3` = 3–24 (avg 13.5). Held interval **11 tics** (≈3.2 throws/s ≈ 43 DPS: between pistol ~25 and chaingun ~87) |
| Alt fire | **Fan of 3** (−6°, 0°, +6°), costs 3 ammo, held interval 24 tics |
| Silent | The weapon has `+WEAPON.NOALERT`: throwing does **not** call `P_NoiseAlert`. Impact sounds don't wake monsters either (they are plain sounds). Stealth niche. |
| Sticking | A star that hits a **wall, floor or ceiling** stays stuck there as a `ShurikenStuck` pickup (+1 ammo when walked over, 64-unit pickup radius as normal touch); despawns after 60 s; at most 32 per map (oldest removed). A star hitting **sky** or a **liquid** floor (TERRAIN splash / `damage` floor) is lost. |
| Hitting monsters | Damage + flesh sound + blood (normal missile path). The mod remembers which monster holds how many stars; when that monster dies, they **drop** as `ShurikenStuck` pickups around the corpse. Stars hitting non-bleeding/`NOBLOOD` actors bounce off with a clink and drop to the floor. |
| Visuals | 4-point star, steel with a bright edge; 4 spin frames (0°, 22.5°, 45°, 67.5°) at 2 tics each; first-person gloved hand holding a fan of stars with wind-up / release / follow-through frames; pickup sprite (a small pile), box sprite, stuck sprite (star half-buried), HUD icon. |
| Sounds | Throw "whoosh", wall "clink", flesh "thunk", pickup "shing", box pickup, weapon raise "slide". |
| Map placement | On each map load the mod places the weapon and ammo deterministically (§6.4); `give Shuriken` / `summon ShurikenPickup` work from the console. |

Balance numbers live in one table (`tables.rs`) and are used both for
registration and for tests.

## 2. What exists vs. what is missing

| Need | Exists | Missing |
|---|---|---|
| New classes from a mod | `reg_class_begin/end`, `reg_class_property_i32/str`, `reg_class_flag` → `import_script_class` (copies the parent, applies props/flags) | — |
| Own states | `reg_state_label`, `reg_state(sprite, frame, tics, flags, callback_id)` are recorded in `RegisteredClass.states` | **Not merged** into `StateTable`; no flow keywords (`Loop/Stop/Goto/Wait`), no native action binding, no action args |
| Actions | Native actions via `call_action_args` (DECORATE path) | Binding from module states; dispatching `callback_id` actions to WASM for actors **and** psprites |
| Weapon / ammo / inventory / projectile properties | `PropId` 1–12, 20–22 (health, speed, radius, …, translation, tag, obituary) | `Weapon.*`, `Inventory.*`, `Ammo.*`, `Damage`, `SeeSound/DeathSound/BounceSound`, bounce props, `Inventory.Icon`, pickup message/sound |
| Flags | `class_flag` 1–11 (SOLID … DONTDRAW) | `MISSILE`, `NOGRAVITY` exists, `DROPOFF`, `NOBLOCKMAP`, `NOTELEPORT`, `BOUNCEONACTORS`, `THRUGHOST`, `INVENTORY.*`, `WEAPON.NOALERT`, `WEAPON.NOAUTOFIRE`, `FLATSPRITE`/`WALLSPRITE` render flags |
| Sprites / graphics | Sprites come from the VFS (`S_START…S_END`, `SoftPatch`) | Any way for a module to provide image data |
| Sounds | SNDINFO + DMX/WAV lumps in the VFS | Any way for a module to provide sound data |
| Weapon slots | KEYCONF `setslot/addslot` (`weapon_slots.rs`) | Registration call |
| Alt fire | — (`Buttons` bits 0–8, 16–19 used) | `ALTATTACK` button, `AltFire`/`AltHold` labels, `A_WeaponReady` alt handling |
| Missile impact info | `ThingDied` event for the missile? No (missiles explode, they don't "die" through the damage path) | What the missile hit (actor / wall / floor / ceiling / sky / liquid) and where |
| Palette | PLAYPAL in the VFS | A read-only `lump_read` import usable at registration (listed in `docs/12` §9, not implemented) |

## 3. Engine work (`SK-E*`)

All new imports follow `docs/30` §2/`docs/27` §10's rules: append-only in the
IDL (`crates/room-script-abi/api/reg.ron`, `common.ron`) and the
`game_fns!`/registration linker tables, SDK wrappers
(`crates/room-script-sdk/src/reg.rs`, new `art.rs`, `sound.rs`), AssemblyScript
mirror (`crates/room-web/as/room.ts`), tests, `docs/12` §15/§16 updates.

### SK-E1 — Module states and actions
1. **Merge states**: in `ModRuntime::merge_classes`
   (`crates/room-sim/src/script_mods.rs`), append each class's recorded
   states to the `StateTable` (new `StateTable::import_script_states(class_id, &[RegCall])`),
   register its labels for that class, then run `inherit_labels` so labels
   not defined by the module still come from the parent (`Spawn`, `Death`, …).
2. **Flow keywords**: add `reg_state_flow(kind, label_ptr, len, offset)` —
   kinds `Loop`, `Stop`, `Wait`, `Fail`, `Goto` (label may be `Super::X` or a
   label of the parent chain). Apply exactly like DECORATE; an unresolved
   `Goto` is a **registration error** (never falls through — see
   `docs/30` N1).
3. **Native actions on states**: `reg_state_action(name_ptr, len, args_ptr, args_len)`
   sets the action of the *last* appended state; `args` is the DECORATE
   argument string (`"\"ShurikenMissile\", 0, true"`), parsed by the existing
   `deco_eval` so every native action (`A_WeaponReady`, `A_Lower`, `A_Raise`,
   `A_ReFire`, `A_FireProjectile`, `A_PlaySound`/`A_StartSound`,
   `A_SpawnItemEx`, `A_Jump`, …) is available. Unknown action names are a
   registration error.
4. **WASM actions**: `reg_state(…, callback_id)` with `callback_id ≥ 0`
   makes the state call `room_dispatch(callback_id, ActionPayload)` when
   entered. `ActionPayload { self_: ActorRef, player: i32 /* −1 or slot */,
   state: StateRef, caller: u32 /* 0 actor, 1 psprite, 2 flash */ }`. For
   psprite states `self_` is the player's body (as in GZDoom) and
   `world.psprite_weapon` is set (needed for ammo). The returned `i64` is a
   `StateRef` to jump to (0 = continue). Wire this both in the actor state
   machine (`room-sim` thinker state advance) and in
   `think_player::set_psprite` (`other =>` branch).
5. **Registration flags**: `reg_state` flag bits: `BRIGHT`, `FAST`,
   `CANRAISE`, `NODELAY`, `OFFSET(x,y)` via a separate
   `reg_state_offset(x, y)` for weapon frames.
6. Fingerprint (`RegistrationSession::fingerprint`) already hashes the call
   list; make sure the new calls are recorded.

### SK-E2 — Weapon, ammo, inventory and projectile properties
Extend `PropId` (append-only) and `apply_script_prop_i32/str`
(`crates/room-sim/src/class.rs`):

| PropId | Kind | Maps to |
|---|---|---|
| `InventoryAmount`, `InventoryMaxAmount` | i32 | `inventory_amount`, `inventory_max_amount` |
| `InventoryPickupMessage`, `InventoryPickupSound`, `InventoryIcon` | str | pickup message / sound / HUD icon |
| `AmmoBackpackAmount`, `AmmoBackpackMaxAmount` | i32 | backpack rules (`pickup.rs`) |
| `WeaponAmmoType` | str | `ammo_type` |
| `WeaponAmmoUse`, `WeaponAmmoGive`, `WeaponSelectionOrder`, `WeaponKickback`, `WeaponSlotNumber` | i32 | existing `ClassDef` fields (`selection_order` exists since WF1) |
| `WeaponReadySound`, `WeaponUpSound` | str | (also fixes `docs/30` N7) |
| `Damage` | i32 | missile damage (`((P_Random()%8)+1)·Damage`) |
| `SeeSound`, `DeathSound`, `BounceSound`, `ActiveSound` | str | existing sound fields |
| `BounceType` (0 none … GZDoom enum), `BounceCountMax`, `BounceFactorPercent`, `WallBounceFactorPercent` | i32 | bounce fields (if the playsim supports them; else SK-E2b) |
| `ProjectileKickBack` | i32 | kickback |

New `class_flag` ids: `MISSILE`, `DROPOFF`, `NOBLOCKMAP`, `NOTELEPORT`,
`BOUNCEONACTORS`, `THRUGHOST`, `NOBLOODDECALS`, `FORCEXYBILLBOARD`,
`WALLSPRITE`, `FLATSPRITE`, `INVENTORY_AUTOACTIVATE`, `WEAPON_NOALERT`,
`WEAPON_NOAUTOFIRE`, `WEAPON_AMMO_OPTIONAL`.
`is_weapon` / `is_ammo` / `is_inventory` must be set when the corresponding
properties are present (same rule as DECORATE in `class.rs`), or when the
parent is `Weapon` / `Ammo` / `Inventory` (see `docs/30` W16 — base classes).

`+WEAPON.NOALERT`: skip `noise_alert` in `fire_weapon` and the `A_ReFire`
branch of `think_player.rs` when the ready weapon has the flag.

### SK-E3 — Generated lumps: graphics and sounds
Design: the module produces **lumps in standard Doom formats**; the host
collects them into an **in-memory PWAD layer** mounted on top of the VFS
(after the mod's own WAD). Everything downstream (sprite lookup, `SoftPatch`,
GPU textures, software renderer, sound system, `drop_weapons_without_sprites`,
web) works unchanged.

Imports (registration scope only):
```
lump_find(name_ptr, len, namespace) -> i32         // common; read-only; −1 if absent
lump_read(index, buf_ptr, cap) -> i32               // common; bytes copied (PLAYPAL, COLORMAP…)
reg_lump(name_ptr, name_len, namespace, data_ptr, data_len) -> i32   // reg; 0 ok
```
- `namespace`: `0 global`, `1 sprites (S_START)`, `2 graphics`, `3 sounds`,
  `4 flats`. Names ≤ 8 chars, uppercase; a name already present in the
  module's own WAD is an error; overriding IWAD lumps requires a manifest
  flag (`override_lumps = true`).
- Limits: 4 MiB total per mod, 256×256 max per graphic, 10 s per sound.
- The SDK provides encoders (pure Rust, `no_std`, `alloc` optional):
  `art::encode_patch(w, h, left, top, &indexed, &mask) -> Vec<u8>` (Doom patch:
  header + column posts; transparent where `mask = 0`) and
  `sound::encode_dmx(rate, &pcm_u8) -> Vec<u8>` (DMX: `u16 3, u16 rate, u32 n,
  16 pad bytes, samples, 16 pad bytes`).
- SNDINFO entries: `reg_sound_alias(logical_ptr, len, lump_ptr, len)` so
  states can use logical names (`"shuriken/throw"`); also `$limit`-style
  options as an int arg.
- Host side: `RegistrationSession` gains `lumps: Vec<GeneratedLump>`;
  `Headless::set_script_mods` returns them; desktop (`room-app`), web
  (`room-web`) and the server verifier mount them as a memory WAD
  (`VfsBuilder` already mounts in-memory WADs in tests via `WadWriter`) and
  invalidate patch/sprite/sound caches. Hot swap (`hot_swap_script_mods`)
  replaces the layer.
- Netplay: generation is deterministic, and the fingerprint hashes the lump
  bytes, so a client with different bytes fails the room's mod check instead
  of desyncing later.

### SK-E4 — Slots, alt fire, missile hit info, misc.
1. `reg_weapon_slot(slot, class_ptr, len, priority)` → KEYCONF
   `addslotdefault` semantics in `WeaponSlots`.
2. **Alt fire**: `Buttons::ALTATTACK = 1 << 9` (the wire field is already
   `u32` → no protocol change); bind `+altattack` (default: right mouse);
   `A_WeaponReady` enters `AltFire` when held (GZDoom `WRF_NOSECONDARY`
   respected), `A_ReFire` in an alt sequence re-enters `AltHold`/`AltFire`;
   `Weapon.AmmoUse2`/`AmmoType2` optional (else primary ammo with an explicit
   `useammo` count in the action). Update `docs/15` bindings and the web
   input hub.
3. **Missile hit info**: when a missile enters its `Death`/`Crash`/`XDeath`
   state, record on the missile actor: `hit_kind` (`1 actor, 2 wall, 3 floor,
   4 ceiling, 5 sky, 6 liquid floor`), `hit_actor` (blocking mobj),
   `hit_normal` (wall normal or ±Z), `hit_line`/`hit_sector`, and `hit_pos`.
   Expose with `actor_get_i32(HIT_KIND)`, `actor_get_ref(HIT_ACTOR)`, and a new
   `actor_hit_info(ref, out_ptr)` (pos xyz + normal xyz as f64). Sky hits
   already remove the missile silently in Doom; give the module a
   `MissileExpired` event (or a `Death` callback with `hit_kind = 5`) so it
   can account for the lost star.
4. **Events**: append `WORLD_THING_DESTROYED` (already planned, `docs/27` C8)
   so the mod can clean up stuck-star bookkeeping; `ThingDied` already exists
   for monsters.
5. `A_FireProjectile` must deplete ammo (fix `docs/30` N2) and honour
   `useammo`; `+WEAPON.NOALERT` (SK-E2).

## 4. The mod: structure and registration

### 4.1 Layout
```
mods/doom1-shuriken/
  Cargo.toml            # standalone guest crate, cdylib+rlib, opt-level "z" (copy doom1-survival's)
  room.toml             # manifest, §4.6
  README.md
  src/
    lib.rs              # RoomMod impl, export_mod!, event routing
    tables.rs           # balance numbers, names, colours (single source of truth)
    fixed.rs            # Q16.16 helpers, const sine table (256 entries), isqrt
    raster.rs           # polygon scanline fill, outline, shading, supersample-free
    palette.rs          # PLAYPAL load (lump_read) + nearest-colour LUT (32³, built once)
    art.rs              # vector shapes for every sprite → indexed pixels → reg_lump
    synth.rs            # integer PCM synth → DMX → reg_lump + reg_sound_alias
    classes.rs          # reg_class_*/reg_state*/reg_weapon_slot
    behaviour.rs        # impact handling, sticking, retrieval, drops, placement
```
No art or sound files in the repo. `scripts/room-server.sh mods` already
builds every `mods/<dir>` with a `Cargo.toml`.

### 4.2 Determinism rules for generation
- Integer / Q16.16 maths only; rotation uses a **const 256-entry sine table**
  in `fixed.rs` (game `math_*` imports are play-scope and not available during
  registration).
- No `f32/f64` arithmetic in generation (or only with exactly-representable
  operations and no transcendental functions) — simplest is to ban floats in
  `raster.rs`/`synth.rs` (clippy `float_arithmetic` lint on those modules).
- Noise for sound uses a fixed-seed xorshift32 in `synth.rs`.
- Iteration in index order; no hashing of pointers.
- Unit test: SHA-256 of every generated lump is pinned in the test (changes
  must be deliberate).

### 4.3 Art generation (`art.rs`, `raster.rs`, `palette.rs`)
1. Read `PLAYPAL` (palette 0) via `lump_find`/`lump_read`; build a 32³
   RGB→index LUT once (nearest colour, Euclidean in RGB, ties → lower index).
   Index 247 (often transparent-looking cyan in Doom) is never used as a
   colour; transparency is the patch mask.
2. Shapes are described as polygons in a 1/16-pixel integer grid with a
   colour ramp id; the rasteriser fills with even-odd scanlines at pixel
   centres, then draws a 1-px dark outline (Doom sprites have dark borders),
   then applies simple lighting: steel ramp chosen by the dot of the face
   normal with a fixed light direction (precomputed per face), plus a 1-px
   bright edge highlight.
3. Sprites to generate (names follow Doom conventions; `0` = all rotations):

| Lump(s) | Size | Content |
|---|---|---|
| `SHKMA0`–`SHKMD0` | 16×16 | Flying star, 4 spin frames (rotations 0°, 22.5°, 45°, 67.5°) |
| `SHKSA0` | 16×10 | Star stuck in a surface (half buried, seen edge-on; pivot at the bottom) |
| `SHKPA0` | 20×12 | Single star lying on the floor (weapon/ammo pickup look) |
| `SHKBA0` | 24×16 | Box of stars (ammo box pickup): wooden box + 3 visible stars |
| `SHKWA0` | 28×16 | Weapon pickup: fan of 5 stars on a cloth wrap |
| `SHKGA0` | ~120×80 | First-person Ready: gloved hand bottom-right holding a fan of 3 stars |
| `SHKGB0` | ~130×90 | Wind-up: hand pulled back/up |
| `SHKGC0` | ~110×70 | Release: arm forward, hand open, no star |
| `SHKGD0` | ~110×70 | Follow-through: hand lower, reaching for next star |
| `SHKGE0` | ~130×90 | Alt wind-up: wider fan of 5 stars |
| `SHKIA0` | 16×16 | HUD / status bar icon |

   Psprite offsets (`left/top` in the patch header) are set so the hand sits
   at the bottom-right like vanilla weapons: `left ≈ −(160+20)`, `top ≈ −(100+30)`
   relative to `WEAPONTOP` conventions (verify with `room-ui/src/weapon.rs`
   `psprite_pos` and the existing `weapon.rs` tests; status-bar shift is
   applied by the shell).
4. Register each with `reg_lump(name, SPRITES, encode_patch(...))`.
5. Optional variants (6-point star, gold skin) chosen by manifest options
   (§4.6) — never by local cvars, so every client generates the same bytes.

### 4.4 Sound generation (`synth.rs`)
11025 Hz, 8-bit unsigned (Doom DMX), all integer:

| Logical name | Lump | Recipe |
|---|---|---|
| `shuriken/throw` | `DSSHKTHR` | 180 ms band-passed noise (two one-pole filters) with a downward cutoff sweep, fast attack, exponential decay |
| `shuriken/clink` | `DSSHKCLK` | 3 damped sine partials (2.1, 3.7, 5.9 kHz; table sine), 250 ms, slight random detune per partial (fixed seed) |
| `shuriken/flesh` | `DSSHKFLS` | 90 ms low noise burst + 140 Hz thump |
| `shuriken/pickup` | `DSSHKPKP` | 2 short metallic pings rising, 200 ms |
| `shuriken/box` | `DSSHKBOX` | wood knock (noise burst through resonant filter at 400 Hz) + ping |
| `shuriken/up` | `DSSHKUP` | soft cloth slide (noise, low-passed, 300 ms) |

Register with `reg_lump(.., SOUNDS, encode_dmx(..))` and
`reg_sound_alias(logical, lump)`.

### 4.5 Classes and states (`classes.rs`)
What the mod registers, written as DECORATE for clarity (the code issues the
equivalent `reg_*` calls):

```
actor ShurikenAmmo : Ammo
{
  Inventory.Amount 1
  Inventory.MaxAmount 30
  Ammo.BackpackAmount 10
  Ammo.BackpackMaxAmount 60
  Inventory.Icon "SHKIA0"
  Inventory.PickupMessage "Picked up a shuriken."
  Inventory.PickupSound "shuriken/pickup"
  States { Spawn: SHKP A -1  Stop }
}

actor ShurikenBox : ShurikenAmmo
{
  Inventory.Amount 10
  Inventory.PickupMessage "Picked up a box of shurikens."
  Inventory.PickupSound "shuriken/box"
  States { Spawn: SHKB A -1  Stop }
}

actor ShurikenStuck : ShurikenAmmo      // retrievable star (spawned at runtime)
{
  Inventory.Amount 1
  +NOGRAVITY                            // stays where it stuck (walls/ceilings)
  States { Spawn: SHKS A 2100 Stop }    // 60 s, then disappears
}

actor Shuriken : Weapon
{
  Tag "Shuriken"
  Obituary "%o was diced by %k's shuriken."
  Weapon.AmmoType "ShurikenAmmo"
  Weapon.AmmoUse 1
  Weapon.AmmoGive 10
  Weapon.SelectionOrder 1600            // after shotgun, before pistol
  Weapon.SlotNumber 8
  Weapon.UpSound "shuriken/up"
  Weapon.Kickback 50
  +WEAPON.NOALERT
  Inventory.PickupMessage "You got the shurikens!"
  States
  {
  Spawn:    SHKW A -1                    Stop
  Ready:    SHKG A 1 A_WeaponReady       Loop
  Deselect: SHKG A 1 A_Lower             Loop
  Select:   SHKG A 1 A_Raise             Loop
  Fire:
    SHKG B 4
    SHKG C 2 A_FireProjectile("ShurikenMissile", 0, 1)   // useammo = 1
    SHKG C 0 A_StartSound("shuriken/throw", CHAN_WEAPON)
    SHKG D 5
    SHKG A 4 A_ReFire                    // held interval 4+2+5 = 11 tics
    Goto Ready
  AltFire:
    SHKG E 6
    SHKG C 2 A_FireProjectile("ShurikenMissile", -6, 1)
    SHKG C 0 A_FireProjectile("ShurikenMissile",  0, 1)
    SHKG C 0 A_FireProjectile("ShurikenMissile",  6, 1)
    SHKG C 0 A_StartSound("shuriken/throw", CHAN_WEAPON)
    SHKG D 8
    SHKG A 8
    SHKG A 6 A_ReFire                    // held interval 24 tics
    Goto Ready
  }
}

actor ShurikenMissile
{
  Radius 6
  Height 6
  Speed 30
  Damage 3
  Projectile                             // = +MISSILE +NOGRAVITY +NOBLOCKMAP +DROPOFF +NOTELEPORT
  SeeSound ""                            // sound is played by the weapon
  DeathSound ""                          // impact sound chosen by the mod (clink/flesh)
  +FORCEXYBILLBOARD
  States
  {
  Spawn:  SHKM ABCD 2                    Loop
  Death:  TNT1 A 0 ShurikenImpact()      // WASM action (callback), §6.1
          Stop
  XDeath: TNT1 A 0 ShurikenImpact()
          Stop
  }
}
```
Plus `reg_weapon_slot(8, "Shuriken", 0)`. All names are exported in
`tables.rs` so other mods can `class_find("Shuriken")`.

Classes inherit from `Ammo` / `Weapon`. If `docs/30` W16 (base classes) has
not landed, use `Clip`/`Pistol` as parents and override everything (the
inherited states are replaced by the module's labels), and say so in the
README.

## 5. Startup sequence

```
room_register():
  1. pal = palette::load()                       // lump_read("PLAYPAL")
  2. for each sprite in art::SPRITES: px = raster(shape, pal); reg_lump(name, SPRITES, encode_patch(px))
  3. for each sound in synth::SOUNDS: pcm = synth(recipe); reg_lump(lump, SOUNDS, encode_dmx(pcm)); reg_sound_alias(logical, lump)
  4. classes::register()                         // ammo, box, stuck, weapon, missile (states + actions)
  5. reg_weapon_slot(slot, "Shuriken", 0)
  6. register the event handler (export_mod! does this): LOADED, TICK (1 Hz bookkeeping), THING_DIED, THING_DESTROYED
Host: merges classes/states, mounts the generated-lump layer, refreshes caches, records the fingerprint.
```
Budget: generation must finish well within the registration fuel budget
(50 M instructions, `docs/12` §4.2). Rough estimate: ~12 sprites ≤ 130×90
px + 6 sounds ≤ 3 k samples each ≈ a few M instructions. Measure in a test
and keep a 5× margin.

## 6. Runtime behaviour (`behaviour.rs`)

### 6.1 `ShurikenImpact` (WASM action on the missile's Death/XDeath)
Read `hit_kind`, `hit_actor`, `hit_pos`, `hit_normal` (SK-E4.3):

| hit_kind | Action |
|---|---|
| actor (bleeds) | Play `shuriken/flesh` at the impact; add 1 to that actor's stuck count (`stuck_in: [(Actor, u8); 64]`, oldest-out). |
| actor (`NOBLOOD` / invulnerable / barrel) | Play `shuriken/clink`; spawn `ShurikenStuck` on the floor below the impact with gravity (spawn at `hit_pos`, then clear `NOGRAVITY` via a flag import or spawn a gravity variant `ShurikenDropped`). |
| wall | Play `shuriken/clink`; spawn `ShurikenStuck` at `hit_pos − normal·2`, angle facing out of the wall (`WALLSPRITE` render flag), `NOGRAVITY`. |
| floor | Spawn `ShurikenStuck` lying flat (`FLATSPRITE`) at floor z. If the floor is liquid (TERRAIN splash or damaging sector): no star, splash only. |
| ceiling | `ShurikenStuck` at ceiling z − 2, `NOGRAVITY`. |
| sky | Nothing (lost). |

Keep a ring of at most 32 stuck stars per map: when full, `destroy()` the
oldest. Use `WORLD_THING_DESTROYED` to drop entries that were picked up or
expired.

### 6.2 Drops from dead monsters
On `ThingDied { thing }`: if `thing` is in `stuck_in`, spawn that many
`ShurikenDropped` pickups around the corpse (deterministic offsets: 8 units on
a circle at angles from the fixed sine table, `CHECK_POSITION`), remove the
entry.

### 6.3 Retrieval
`ShurikenStuck`/`ShurikenDropped` are normal ammo pickups (touch to collect),
so no mod code is needed. Stars stuck high on walls are reachable only if the
player can touch them (Doom touch uses the 3D box), which is intended.

### 6.4 Placement on map load (`WORLD_LOADED`)
Deterministic, using the playsim RNG (`game::random`) after the map is loaded:
1. **Weapon**: on the first map of an episode (or any map if the player
   doesn't own it yet and `place_weapon = true`): spawn `Shuriken` at the
   first item spot (from `actors_of_class(NULL)` filtered to pickups) that is
   ≥ 512 units from player 1's start and reachable (same validation as
   `docs/27` §6.1 spots: floor/ceiling gap ≥ 56).
2. **Ammo**: replace `ammo_replace_percent` % of `Clip` pickups with
   `ShurikenBox` (destroy the clip, spawn the box at the same spot);
   deathmatch: also next to every `Shotgun`.
3. Never touch maps where the mod is disabled; never change anything when
   loading a save (`Loaded { is_save_game }`).

### 6.5 Netplay, demos, saves
- Everything is play-scope and deterministic; demos recorded with the mod
  play back with the mod.
- `stuck_in` / ring state lives in module memory → needs module memory in
  saves (`docs/27` C7) for exact save/load; until then, on load rebuild the
  ring from `actors_of_class("ShurikenStuck")` and accept that stars inside
  monsters are not dropped after a load (document it).
- Royale/Survival compatibility: classes are global; `docs/28` loot tables can
  add `Shuriken`/`ShurikenBox` via `class_find` when present.
